# ZS-RAG 新版前端分批修改计划

界面参考 Paperclip。以原版 `web/` 的可用功能及 RAGFlow Go API 为对照，保留所有原版功能。原版与新版通过根目录 `docker-compose-dev.yml` 同时运行，原版 9222，新版 9223。尚未迁移的业务继续通过原版入口访问。

| 批次 | 页面范围 |
| --- | --- |
| 1 | 单侧栏、工作台、浅色和深色主题 |
| 2 | 登录、退出、会话与权限处理 |
| 3 | 知识库列表和创建 |
| 4 | 知识库文档管理、配置与解析，含预览、分块和元数据 |
| 5 | 知识库检索测试、图谱、编纂与日志 |
| 6 | 文件管理与技能 |
| 7 | 问答助手，含分享和嵌入 |
| 8 | 知识检索，含公开分享 |
| 9 | 智能体与工作流，含模板、运行、日志及分享 |
| 10 | 数据管道及运行结果 |
| 11 | 记忆 |
| 12 | 用户设置，含模型、团队、API 密钥、MCP、数据源、聊天渠道及编纂模板 |
| 13 | 管理后台 |

## 表单样式

新版的文本、邮箱、密码、数字输入框、下拉选择和多行文本统一使用 `src/form-controls.css` 的边框、圆角、背景与灰阶焦点高亮。带图标的搜索框使用 `.form-field` 包裹，焦点高亮放在整框上。新增页面沿用这些规则和浅深色主题令牌。

## 每批验收和确认

1. 开工前从原版页面追到 Go API，记录入口、操作、方法、路径、参数、权限和结果。包括详情页、弹窗、分享链接和功能开关控制的入口。
2. 在开发 Compose 里使用同一个 Go 后端对照两版。读操作比较同一份数据，写操作使用独立测试数据并核对结果。覆盖适用的直达链接、刷新、空数据、失败、权限、上传下载、流式响应及异步任务。
3. 交付当前批次的预览链接、验收路径、对照结果和未验证项。功能有缺失或验证遇阻时，该批保持待验收。
4. 停下来等用户明确确认。收到修改意见则在当前批次调整并重新交付。用户确认后才正式切换对应菜单并开始下一批。全部批次完成后再按原版路由和操作做一次全量核对。

## 第一批功能对照

- 工作台通过 `GET /api/v1/system/dashboard?period=24h|7d|30d` 读取统计。核对刷新与更新时间、知识库和文档数量、存储用量、问答调用趋势、助手排行、召回排行、文件类型、Token 总量与分项及近 30 日趋势。嵌入调用量目前没有历史数据。
- 新版工作台的最近知识库通过 `GET /api/v1/datasets?page=1&page_size=3&sort=update_time:desc` 读取。此区块和快速搜索属于新版入口，点击仍打开原版知识库详情。
- 原版首页的新建入口对应 `/datasets?isCreate=true` 和 `/chats?isCreate=true`，排行链接打开对应原版详情。创建动作、账户入口和权限仍由原版页面和现有 Go API 处理。
- 桌面验收 Paperclip 单侧栏和工作台布局，移动端验收菜单展开及快捷搜索。主题默认跟随系统，手动选择在刷新后保留。

第一批工作台、侧栏和主题已由用户确认。

## 第二批功能对照

| 原版入口 | Go 接口 | 新版行为 |
| --- | --- | --- |
| 登录页及 `/login` | `POST /api/v1/auth/login` | 邮箱与密码登录，沿用原版密码编码和 RSA 公钥，登录成功进入工作台 |
| 登录页的注册入口 | `GET /api/v1/system/config`、`POST /api/v1/users` | 仅在后端开启注册时显示入口，校验昵称，注册成功返回登录 |
| 已有会话访问登录页 | `GET /api/v1/users/me` | 验证会话后返回工作台，区分失效与服务错误 |
| 工作台的会话和权限 | `GET /api/v1/system/dashboard`、`GET /api/v1/datasets` | 刷新后沿用同主机的后端会话 Cookie，401 进入登录页，403 展示权限提示 |
| 账户区退出 | `POST /api/v1/auth/logout` | 由后端撤销会话，退出后返回新版登录页 |

未迁移的业务菜单仍跳转原版。两个前端端口的浏览器本地存储独立，原版继续通过自身登录流程建立其会话。

第二批登录、会话与退出已由用户确认。

## 第三批功能对照

| 原版操作 | Go API | 新版验收点 |
| --- | --- | --- |
| 知识库列表、搜索、分页 | `GET /api/v1/datasets` | 按关键词和所有者查询，支持卡片与列表切换，统一每页 10 条，显示文档数、更新时间、模型、解析方式及解析状态 |
| 所有者筛选 | `GET /api/v1/datasets?type=filter` | 多选、清除筛选，并用原版的 `owner_ids` 参数 |
| 创建 | `POST /api/v1/datasets` | 名称、Embedding 模型、内置解析器或数据管道及其版本，创建后打开原版详情 |
| 创建选项 | `GET /api/v1/models`、`GET /api/v1/models/default`、`GET /api/v1/pipelines?type=builtin`、`GET /api/v1/agents/versions?category=dataflow` | 加载实际可用选项，预填可用的默认模型，切换解析方式时清除上一种方式的参数 |
| 列表操作 | `PUT /api/v1/datasets/:id`、`DELETE /api/v1/datasets` | 重命名、确认删除、权限拒绝、刷新列表，删除当前页最后一项时回到上一有效页 |

工作区侧栏的「知识库」打开新版 `/datasets`。现有详情、配置及文档入口继续使用原版。

第三批列表已确认，侧栏合并为一个知识库入口。Compose 构建、真实 Go 接口的未登录拒绝，以及浏览器中用测试响应验证的筛选、分页、重命名、删除和两种创建请求均已通过。真实租户的创建、重命名和删除仍待验收。

## 数据管道与编译算子双入口

新版侧栏与智能体页内标签共用分类和功能。侧栏的数据管道和编译算子入口只显示当前分类，智能体入口保留三个分类标签。数据管道保留列表、模板、内置管道、画布及运行结果，沿用 `/api/v1/agents` 和 `/api/v1/pipelines`。编译算子保留列表及模板组的创建、编辑和删除，沿用 `/api/v1/agents` 的分类查询和 `/api/v1/compilation-template-groups` 的写入接口。

已用测试数据验证两种入口、侧栏选中状态、刷新和编译算子编辑器入口。真实后端的保存与管道运行待验收。
